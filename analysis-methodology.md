# Network Traffic Analysis Methodology

## Phase 1 — Define scope
Document the authorized devices, isolated network, capture period, interfaces, and exclusions.

## Phase 2 — Capture
Use tcpdump to capture a short, bounded trace. Record the command and interface. Prefer capture filters that limit collection to the traffic required for the exercise.

## Phase 3 — Validate the capture
Check file size, packet count, timestamp range, and whether the expected test traffic is present.

## Phase 4 — Protocol and endpoint analysis
Use Wireshark Protocol Hierarchy, Conversations, Endpoints, and packet details to understand normal communication patterns.

## Phase 5 — Identify anomalies
Look for observations such as:
- Unexpected destination addresses or ports
- Repeated connection attempts or unusual SYN patterns
- DNS queries with unusual frequency or naming patterns
- Unexpected cleartext protocols
- Repeated retransmissions or connection resets
- Unusual data volume or timing

These are investigative leads, not standalone proof of compromise. Consider the lab context and benign explanations.

## Phase 6 — IDS correlation
Compare Snort alerts with the corresponding packets. Check rule meaning, packet direction, timestamps, and false-positive possibilities. An alert generated by a broad educational rule is not a confirmed incident.

## Phase 7 — Triage and reporting
Record evidence, confidence, impact, and recommended next steps. Separate confirmed facts from hypotheses.

## Phase 8 — Defensive recommendations
Depending on evidence, recommend network segmentation, firewall policy review, patching, secure protocol use, endpoint investigation, DNS monitoring, or additional authorized collection.
